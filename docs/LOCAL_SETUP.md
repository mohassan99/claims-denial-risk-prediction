# Local setup: everything that is not in git

Git holds code and docs. Everything below is gitignored, and none of it should exist only in
a cloud session. Each item lists where the durable copy lives and how to rebuild it.

| Gitignored item | Durable source | Rebuild |
|---|---|---|
| `.env` (secrets and IDs) | You. Values come from the portals listed below. | `bash scripts/make_env.sh` (prompts; secrets typed hidden) |
| `venv/` | `requirements.txt` | `python -m venv venv`, `source venv/Scripts/activate`, `pip install -r requirements.txt` |
| `data/raw/*` (CMS CSVs) | CMS Synthetic Medicare Claims PUF (see `src/load_data.py` docstring) | Download and unzip into `data/raw/` |
| `data/processed/*` | Raw CSVs plus the code | `python src/load_data.py`, then `build_target_and_split.py`, then `build_features.py` |
| `reports/xgboost_model.json`, `reports/xgboost_model_meta.json` | Azure ML model registry (`claims-denial-xgboost`) | `bash deploy/deploy.sh download-model` (expect content hash `11f409f72fc4c45e`), or `python src/fit_xgboost.py` (deterministic) |
| `reports/phase5/val_predictions.parquet`, `reports/phase5/test_predictions.parquet` | Copied to your machine by the 2026-09-30 session | val: `python src/evaluate_test.py --stage val`. test: do NOT regenerate (the test stage runs once; deleting `test_results.json` to rerun would void that record) |
| `reports/phase4_runs/` (agent transcripts, if large) | Regenerated by the Phase 4 evaluation script | see docs/PHASE4.md when it exists |

## Where each `.env` value comes from

- `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`: Azure portal (subscription overview and Microsoft Entra ID overview).
- `AZURE_CLIENT_ID`: the app registration `claims-denial-deployer` (Entra ID, App registrations).
- `AZURE_CLIENT_SECRET`: shown only once when created. If lost, create a new secret on that app
  registration (Certificates and secrets). The current one expires about 90 days after 2026-09-27.
- `DATABRICKS_HOST`: not a secret, in `.env.example`. `DATABRICKS_TOKEN`: a personal access token
  from your Databricks user settings (developer section). Revoke it when the project is done.
- `ANTHROPIC_API_KEY`: created in the Anthropic Console. Use a dedicated key for this project so
  you can revoke it alone.

## Rules

- Never paste a secret into chat if you can avoid it. `scripts/make_env.sh` exists so you do not have to.
- A secret that was pasted into a chat or committed anywhere should be rotated.
- If a step works only in a cloud session because of a file or value only that session holds, that is a bug in the docs; add the missing row above.
